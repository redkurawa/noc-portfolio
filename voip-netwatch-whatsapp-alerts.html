VoIP Host Availability Monitoring

A MikroTik router pings the devices of VoIP clients and sends a WhatsApp message when a device stops answering and again when it comes back. The NOC learns that a client has a network problem before the client reports it.

Problem Client-side network or device failures were found only after the client reported them.
Approach Watch each client host with Netwatch (ICMP ping). On DOWN, a script confirms the outage and posts a message to a WhatsApp gateway. On UP, a second script posts a recovery message.
Tools MikroTik RouterOS · Tools → Netwatch · RouterOS scripting · /tool fetch · WhatsApp gateway (HTTP API)
Result Host status changes arrive as WhatsApp messages with the time of each event. See the masked screenshot below.

🔧 How it works

Client host answers ping or not
→
MikroTik Netwatch runs the Up or Down script
→
WhatsApp gateway receives an HTTP POST
→
NOC phone gets the message
  1. Netwatch pings every host on its list. When a host stops answering, Netwatch runs the Down script.
  2. The Down script pings the host again once per second for 60 seconds. Only if no reply arrives does it send the DOWN message.
  3. When the host answers again, Netwatch runs the Up script, which waits 5 seconds and sends the UP message.
  4. Both scripts send the message with /tool fetch as an HTTP POST to the WhatsApp gateway on the internal network.

🛠️ What I set up

  • Added the Up and Down scripts in RouterOS.
  • Added each client host to monitor in Tools → Netwatch.
  • Assigned the scripts in the Up and Down fields of each Netwatch entry.

📜 Scripts

The recipient phone number and the client label are masked. The gateway address is a private IP and is left as is.

Up script

netwatch · Up script 
:local pesan "$host CLIENT UP"

:delay 5s
/tool fetch http-header-field="content-type: application/x-www-form-urlencoded" \
    http-method=post \
    http-data="phone=628xxxxxxxxxx&message=$pesan" \
    url="http://10.50.50.101:3000/send/message" \
    keep-result=no;

Down script

netwatch · Down script 
:if ([/ping $host interval=1s count=60] = 0) do={

    :local pesan "$host%20CLIENT%20DOWN"

    /tool fetch \
        http-header-field="content-type: application/x-www-form-urlencoded" \
        http-method=post \
        http-data="phone=628xxxxxxxxxx&message=$pesan" \
        url="http://10.50.50.101:3000/send/message" \
        keep-result=no

}

What the scripts do

$host The address of the Netwatch entry that triggered the script, so one script serves every monitored host.
/ping … count=60 Returns the number of replies. A result of 0 means the host stayed silent for 60 seconds, which filters out a single lost packet before an alert is sent.
:delay 5s Short pause before the UP message is sent.
/tool fetch HTTP POST with form-encoded phone and message fields to the gateway endpoint /send/message.
%20 URL-encoded space, so the whole message stays in one field.

📲 Evidence

Screenshot of the WhatsApp chat that receives the notifications. Each message shows the host address, a client label and UP or DOWN, with the time it arrived.

📌 Scope and limits

  • Netwatch checks ICMP reachability. A host that answers ping can still have a failed VoIP service, and a host that blocks ICMP looks down.
  • Delivery depends on the WhatsApp gateway and its connection. If the gateway is unreachable, no message is sent.
  • The gateway request is plain HTTP on a private network and carries no authentication in the script.
